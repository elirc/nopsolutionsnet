# 01 — Codebase Cartography

Build the map before the opinions. This module answers: what kind of system is this, where does each concern live, which files to read in what order, and how the six most important flows actually run.

Read in order:
1. [01-system-map.md](01-system-map.md) — the shape of the repo and who owns what
2. [02-file-reading-order.md](02-file-reading-order.md) — 28 files, junior→senior paths
3. [03-domain-glossary.md](03-domain-glossary.md) — the nouns, with code locations
4. [04-runtime-and-tooling-map.md](04-runtime-and-tooling-map.md) — build, run, test, boundaries
5. [05-key-flows.md](05-key-flows.md) — six end-to-end traces (the module's centerpiece; everything else in the curriculum links back here)

Transferable skill: *cartography is repeatable.* The sequence — manifests → entry point → DI registrations → one read flow → one write flow — maps any codebase in a day. Interviewers ask "how do you approach an unfamiliar codebase?"; this module is your answer, with receipts.
